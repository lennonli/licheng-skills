# 八字排盘与命书生成

## 铁律

八字解读的成败，八成在**排盘**。日柱要靠六十甲子连续推算、月柱要卡节气交接的具体时刻、时柱要看真太阳时、农历还要换算——**凭记忆或心算干支必然出错，而且错得毫无征兆**：日主一错，整篇解读全部作废，读起来却依然通顺。

> **一切干支、节气、农历、大运的数字，全部交给 `scripts/paipan.py` 计算。
> 绝不手工推算，绝不声称"已验算"而其实没跑脚本，绝不在没有脚本输出的情况下写出任何一个干支。**

脚本的日柱用儒略日独立推算（锚点 1949-10-01 甲子日），节气与农历用天文历算，真太阳时按出生地经度与均时差校正。断语部分才由你来写。

## 运行环境

**本技能完全离线**：`vendor/` 已内置 lunar-python（纯 Python，约 1.1MB），脚本会自动从那里加载。**不需要联网、不需要 pip、不会触发沙箱网络审批。**

只需系统 Python 3.8+，无第三方依赖。若 `vendor/` 意外缺失，脚本会退回内置的 Meeus 太阳视黄经算法（节气误差约 ±15 分钟，会在 warnings 中声明），并尝试用清华镜像安装 lunar-python 作为最后手段。

## 工作流

### 第 1 步：收齐输入

必需四项：**出生日期、出生时间、出生地、性别**。缺项一次问完，别逐条挤牙膏。

- **日期**：公历或农历都行，**必须问清是哪一种**——农历八月廿二与公历8月22日可能相差一个多月，月令与日柱全变。农历还要问是否闰月。
- **时间**：越精确越好。只说"晚上八点左右"也能排，但要在报告中提示临界风险。完全不知时辰时，用 `--time unknown` 排年月日三柱盘（写法见下方「时辰不详的三柱盘」一节）；但先问一句「有没有出生证明、记不记得大概是上午还是晚上」——哪怕只能排除深夜出生，也能消掉日柱的风险。
- **出生地**：常被忽略，但它决定真太阳时。中国东西横跨约 62 个经度，最西端与北京时间差逾 3 小时，**足以让时柱整个错位**。城市名即可（脚本内置常用城市经度表）；冷僻地名（如县城、乡镇）用 `--lon` 直接给经度。
- **性别**：决定大运顺逆，男女运路可能完全相反。

### 第 2 步：排盘

```bash
cd <skill目录>
python3 scripts/paipan.py --date 2000-01-01 --time 00:30 --place 北京 --gender male --json /tmp/chart.json
# 农历：--lunar 2000-11-20 [--leap]
# 冷僻地名：--lon 114.97 代替 --place
# 运势范围：--liunian 12 --liuyue-year 2026 --liuri 30 --liuri-from 2026-10-01
# 时辰不详：--time unknown（只排年月日三柱）
```

读回 JSON。里面已有：四柱、藏干、十神、纳音、五行加权统计、旺衰评分、地支刑冲合害、天干五合、神煞、空亡、调候用神、大运八步与起运时间，以及 **warnings**。

### 第 3 步：先处理 warnings

`warnings` 是这个技能最要紧的输出，**必须在报告显著位置呈现，不能省略、不能淡化**：

| 情形 | 意味着什么 | 怎么写 |
| --- | --- | --- |
| 距交节 < 12 小时 | 月柱在临界，出生时间差一点点整个格局就变 | 写出交节时刻与相差小时数，请用户核对出生证明 |
| 子时跨日界 | 主流「子时换日」与少数派「夜子时不换日」得出**不同日主** | 两盘并列成表，说明本报告取主流算法及理由 |
| 真太阳时校正 > 45 分钟 | 时柱可能整个移位 | 提示务必确认出生地与时间 |
| 时辰不详 | 只有三柱，时柱相关判断全部空缺 | 见「时辰不详的三柱盘」一节 |
| 时辰不详且当天三柱会变 | 出生当天交节，或深夜出生按「子时换日」日柱变成次日 | 写明钟表时段与对应三柱，放进待核实事项和白话版「需要先核实的事」 |

`alt_plate` 非空时，把备盘写进「待核实事项」。

### 第 4 步：读方法论，做判断

按顺序读**两份**参考（都要读）：

- `references/method.md` — 旺衰复核、格局定性、**从格/专旺格的辨析程序**、用神取法、扶抑与调候冲突时的取舍、刑冲合害的实义、神煞分量、大运判吉凶
- `references/interpretation.md` — 日主取象、十神人事含义、性情/六亲/健康/方位行业的写法、**儿童命盘的教养重心**、当下阶段建议、语气与边界、**白话版写法与术语对照**

**定下喜忌后必须重跑一次。** `chart.json` 的 `yongji` 默认由旺衰自动推导，而流年、流月、流日的全部评分都建立在它之上。按 `method.md` 复核出真正的喜用神后，带 `--yong 木,火 --ji 水,金` 重排一次——**特殊格局（从格、专旺）的喜忌与常规相反，不重跑则整份运势吉凶正好颠倒**。

**脚本的 `strength.verdict` 是算法评分，不是终审。** 按 `method.md` 的程序复核：月令是否得地、有无通关、旺神是否受制、是否可能成从格或专旺格。你的判断与算法不一致时以你为准，**但必须在报告里写明改判理由**——这样日后发现不符时能回头复核。

### 第 5 步：写解读，渲染 HTML

把 chart JSON 原样保留，加一个 `analysis` 键写成 merged.json，然后：

```bash
python3 scripts/render.py /tmp/merged.json "$HOME/Desktop/八字命书-<简述>.html"
open "$HOME/Desktop/八字命书-<简述>.html"   # macOS 直接预览
```

输出路径默认放在当前工作目录或桌面，**先问用户想放哪里**。文件名建议 `八字命书-<出生信息简述>.html`。

**写作顺序：先写专业部分（每段写完紧接着写它的「怎么办」），最后写 `plain`（白话版）。** 白话版是专业结论的翻译，不是另起炉灶——先把格局、喜忌、大运判定下来，再把它们译成大白话，这样两边不会打架。白话版渲染在报告**最前面**，绝大多数读者只看这一页。

`analysis` 字段（`plain` 必写，其余可选、越全越好）：

```jsonc
{
  "plain": {                                   // 白话版，置于报告最前；写法见下方「白话版」一节
    "headline": "…",                           // 一句大白话总览（含一个比喻），作白话版标题
    "intro": "…",                              // 可选，一两句引子
    "sections": [{"h": "她是什么样的人", "text": "…", "tip": "…"}],   // 按下方顺序逐节写；tip 为该节的「怎么做」
    "closing": "…"                             // 一句话收尾
  },
  "title": "杀印相生 · 甲木身弱转中和",       // 一句话点出全局，作大标题
  "day_master": "日主甲木——…",                // 日主取象与性情底色
  "strength_reason": "…",                      // 旺衰推导过程，含改判理由
  "geju": "…",                                 // 格局定性：病是什么、药是什么
  "congge": "…",                               // 从格/专旺格辨析，无则省略
  "yongshen": {
    "rows": [{"wx":"火","god":"食伤","why":"暖局泄秀制杀","level":"喜（第一）"}],
    "note": "…",                               // 取用的核心一句
    "tiaohou_note": "…"                        // 扶抑与调候是否一致，不一致如何取舍
  },
  "structures": [{"k": "丁壬合（月干合日主）", "text": "…", "tip": "…"}],   // 逐条：结构名 / 实义 / 怎么办（也可写成一段字符串）
  "shensha_note": "…",
  "dayun": [{"gz":"甲午","judge":"大吉","text":"…","tip":"…"}],   // tip：这步运里怎么做
  "dayun_summary": "…",
  "liunian": [{"year": 2026, "text": "…", "tip": "…"}],     // 逐年补充，只写需展开的年份；tip：这一年怎么做
  "liunian_note": "…", "liuyue_note": "…", "liuri_note": "…", "extras_note": "…",
  "character": "…", "liuqin": "…", "health": "…", "career": "…",
  "advice": "…",                               // 针对当下正在走的那一步大运
  "summary": "…",                              // 一页总结
  "todo": "…",                                 // 待核实事项，warnings 与 alt_plate 写这里
  "tips": {                                    // 每段解读之后的「怎么办」，键名＝所跟随的字段名
    "day_master": "…", "geju": "…", "yongshen": "…", "shensha_note": "…",
    "dayun_summary": "…", "liunian_note": "…", "liuyue_note": "…", "liuri_note": "…",
    "extras_note": "…", "character": "…", "liuqin": "…", "health": "…", "career": "…"
  }
}
```

文本可用 `**粗体**`、`【标记】`、以 `- ` 开头的行成列表、空行分段。`tips` 的值可以是字符串，也可以是字符串数组（每项渲染成一条）；任一文字字段也可写成 `{"text": "…", "tip": "…"}`，效果相同。

`judge` 取值必须是：**大吉 / 吉 / 参半 / 平 / 需谨慎 / 不利**（决定时间轴配色）。`dayun` 数组的 `gz` 要与 chart JSON 中的大运干支**逐字对应**，否则配不上色。当下正在走的那一步会自动高亮。

### 第 6 步：交付

告诉用户文件路径，回复里只写三件事：**格局一句话、最要紧的一条提醒、需要核实的事项**。报告已在文件里，不要在对话中复述全文。

**对话回复也用白话。** 三件事都按白话版的口径写，不堆术语；术语非用不可时，后面括号带一句解释。用户想看专业推导，自然会往报告后面翻。

## 白话版（报告最前面的那一页）

读命书的人大多不懂命理。专业部分写得再准，满篇「财滋弱杀」「官杀混杂」，读者也只能看个热闹。**白话版是写给这些人的，是整份报告最常被读到的部分，必须写。**

**三条硬规矩：**

1. **不出现命理术语。** 干支、十神、五行生克、格局名、神煞名、「大运」「流年」「喜用神」一律不用。实在绕不开（例如要解释生肖为何与民俗不同），用一句话当场解释。术语与白话的对照见 `references/interpretation.md` 第 11 节。
2. **不新增判断。** 白话版的每一句都要在专业部分找得到出处，只翻译、不加戏；专业部分没写的结论，白话版也不写。
3. **时间用年龄和公历年份。** 写「28 到 37 岁」「2027 年」，不写「甲戌运」「丁未年」。

**固定顺序**（`sections` 按此逐节写，某节确无内容可省）：

1. **一句话总览**（`headline`）——一个贯穿全篇的比喻 + 这个人的核心处境
2. **是什么样的人**——长处、短处，短处写得比长处具体
3. **最需要什么**——即用神的白话：什么东西能让他/她站稳
4. **人生节奏**——哪段顺、哪段紧、现在在哪、转折在哪一年
5. **现在该怎么做**——当下阶段的行事原则，具体到「不合伙、不担保」这种程度
6. **感情 / 家庭**（儿童命盘改写为「怎么带这个孩子」）
7. **工作**
8. **身体**
9. **需要先核实的事**——warnings 与 alt_plate 的白话版，有则必写
10. **一句话**（`closing`）——对应专业部分的「核心一句」，最后把主动权交回给读者

**人称**：给本人看用「你」；替他人看用「她/他」；儿童命盘写给家长，用「孩子」。

**篇幅**：800–1500 字，手机上两三屏读完。**语气**：像一个懂行的朋友当面跟你讲，坦率、具体、不吓人，也不哄人。

## 每段解读之后的「怎么办」

命理判断只回答「是什么」，读者真正要的是「那我怎么办」。**每一段解读写完，紧跟一个「怎么办」**——渲染器会把它排成段落后的绿色框，大运、流年、关键结构则逐条附在每一项下面。

**必须配「怎么办」的位置：**

| 段落 | 字段 | 「怎么办」回答的问题 |
| --- | --- | --- |
| 日主取象 | `tips.day_master` | 怎么用这个人的天性之长、补天性之短 |
| 格局（病与药） | `tips.geju` | 病怎么防、药从哪里来、现阶段怎么用力 |
| 喜用神 | `tips.yongshen` | 把喜用五行翻译成生活选择（行业、人、环境、作息），**不是买东西** |
| 关键结构 | `structures[].tip` | 每一条刑冲合害各自怎么化解或利用 |
| 神煞 | `tips.shensha_note` | 写进报告的那几个神煞怎么用 |
| 大运 | `dayun[].tip`、`tips.dayun_summary` | 每一步运守还是攻、做什么；整体节奏怎么安排 |
| 流年 | `liunian[].tip`、`tips.liunian_note` | 关口年避开什么、窗口年办什么 |
| 流月、流日 | `tips.liuyue_note`、`tips.liuri_note` | 哪几个月、哪几天适合做什么 |
| 其他解析 | `tips.extras_note` | 居所、方位颜色的实际用法 |
| 性情 | `tips.character` | 每一条短处的对治 |
| 六亲 | `tips.liuqin` | 择偶、婚前婚后、与原生家庭和子女的相处 |
| 健康 | `tips.health` | 检查、饮食、作息、运动、情绪 |
| 方位行业 | `tips.career` | 选方向、定主线、选平台、设红线 |
| 白话版各节 | `plain.sections[].tip` | 同上，用大白话 |

**不配的位置**：旺衰推导（`strength_reason`）、从格辨析（`congge`）属于推导与复核，其行动落在紧随其后的格局一段；当下阶段建议（`advice`）、白话版「现在该怎么做」、待核实事项本身就是行动，不再重复。

**写法规矩：**

1. **正文写判断，「怎么办」写行动，两边不重复。** 正文里出现「宜……」「建议……」的句子，挪进「怎么办」；正文只留「是什么、为什么」。
2. **每条都能直接照做。** 动词开头，带对象、时间或数量：「未来 3–5 年锁定一个能拿到手的执业资格」，不写「多学习提升自己」。
3. **一一对应。** 「怎么办」只回应它前面那段讲到的问题；性情里列了四条短处，就给四条对治。
4. **2–6 条为宜。** 宁少而准，不凑数。
5. **三类内容按需取用**：建议（做什么）、注意（避免什么）、时机（什么时候做）。时机尽量落到公历年份或月份。
6. **守底线**：不推荐法器、收费改名、风水采购；方位颜色写明是辅助；健康类末尾写「不替代医学检查」；不做死亡、重大疾病的时间断言。
7. **已过去的大运**也写一句：怎么看待那段经历、那十年留下的什么值得珍惜——不写成空白。

详细写法与常见结构的对治清单，见 `references/interpretation.md` 第 12 节。

## 断语的质量标准

这决定了报告是"有用"还是"像算命摊"。

**要具体到能行动。** 不写"注意身体"，写"火旺无水，心血管为第一薄弱环节，35岁后建议每年查血压血脂"。不写"事业有成"，写"杀印相生靠专业与平台立身，进讲资历的组织有利，短线投机不利"。

**要指出结构性的坏消息。** 财多身弱就说"机会看得见吃不下"，官杀混杂就说"易遇消耗型关系"。同时给对治——价值在于提示需留意的倾向，不在制造焦虑。

**要区分"命"与"运"。** 大运走忌神的阶段，明确说"这是运，不是能力问题"。这一句对正处在滞运中的人，价值高于任何吉凶判断。

**涉及儿童时，重心放在教养而非吉凶。** 家长能用的是"这孩子服理不服压，宜疏不宜堵"，不是"三十岁发财"。**同一张盘，教养方式不同结果完全不同**——这一点要说破。

**涉及健康时，命理话语要落到可操作的建议**，且不替代就医。"火弱水旺主寒湿"落地就是"保暖、忌生冷、多晒太阳、规律运动"——本身就有实际意义，不必包装成玄学。薄弱环节较重时（尤其心脑血管），直接建议定期体检。

**不要迎合。** 处处是好话的命书没有用。

**流年流月流日守三条分寸**：一是分清颗粒度——大运看十年、流年看基调有意义，**流月流日只作行事节奏参考，绝不可当成对具体事件的预测**；二是流年重点写"关口"与"窗口"，挑评分最低与最高的一两年讲透，不要十二年平均用力；三是流日不写"宜嫁娶忌动土"那一套，而是告诉用户**怎么用这张表**——看颜色安排一个月里哪几天谈事、哪几天只做手头活。建议让用户把"值得留意的日子"记进日历，比每天查表有用。

**每段都要落到「怎么办」。** 只有判断没有行动的段落，等于把问题丢给读者。

**先白话，后专业。** 专业部分是给懂行的人复核用的，白话版是给所有人用的。白话版读完仍不知道「我该怎么做」，这份报告就没写完。

## 底线

- 每份报告都要有免责声明（渲染器已自动加在页脚）
- **不预测死亡、重大疾病的具体时间，不做确定性的凶险断言**
- 不因命理结论劝人放弃医疗、法律或财务上的专业帮助
- 不为改运兜售具体消费（法器、收费改名、风水采购）；方位颜色一类要说清是辅助性的
- 若用户情绪明显低落，或把命理当作困境的唯一出口，**先关照人，再谈盘**

## 时辰不详的三柱盘

`--time unknown` 时，脚本只排年、月、日三柱，时柱为 `null`；旺衰、刑冲合害、神煞、流年流月流日的评分都只按三柱计算。另外多输出两项：

- `three_pillar_segments`：把出生当天钟表 0:00–23:59 逐分钟扫一遍，若因**交节**或**子时换日**（含真太阳时校正）使三柱在当天内变化，列出各时段对应的三柱。非主段会自动写进 `warnings`。
- `hour_scan`：把 12 个可能的时柱逐一代入重算旺衰。渲染器会在命盘下方画成十二宫格。

**写法规矩：**

1. **先看 `hour_scan`，再定旺衰。** 判语集中（例如 12 个里没有一个落到相反方向）——三柱结论可靠，照常写，并在 `strength_reason` 里写明「十二时辰代入，X 个身旺、Y 个中和，没有一个身弱」。判语分散、跨过中和两侧——**喜用只写方向、不下重话**，明说「补上时辰前，喜忌可能翻转」。
2. **不下结论的部分要明写，不能悄悄省略**：子女（时柱为子女宫）、晚年、命宫身宫、时支上的神煞（桃花、驿马等是否落时）、与时支相关的刑冲合害。六亲一节写「子女：时柱不详，不下结论」，必要时只说子女星（食伤 / 官杀）在哪步大运最旺。
3. **`three_pillar_segments` 有非主段时**，在待核实事项和白话版「需要先核实的事」里写清钟表时段和后果（例如「晚上 11 点 24 分以后出生，日主会变」）。
4. **起运误差**：起运按当日正午估算，误差在两个月以内，大运交接写「前后」。
5. **白话版 `intro` 要交代**：这份报告只用了年、月、日三项，能看清大方向，子女与晚年先不下结论。
6. **文件名加「时辰不详」**，便于日后补上时辰后替换。
7. **补救建议放进 todo**：查出生医学证明、问家人；可选「以事定时」——把 12 个时辰各排一盘，对照兄弟排行、父母情况、几件大事的年份，挑最吻合的，准确度有限，只作参考。

## 合婚与多人合盘

用户给两人以上生辰要合婚或看家庭关系时：**每人分别跑一次 `paipan.py`**，再比对四件事——日柱是否同源或互补、年柱是否补上对方所缺的配偶星、两造地支合起来是否形成新的三合/三会局（尤其是否叠加了双方共同的忌神）、双方喜用神是否一致或冲突。

结论落到可操作处：共同的居住朝向与色调、谁更适合承担推动与决断的角色、财务上的分工与设防、与长辈关系的边界。**不要断"合不合适"**——写清各自结构与需留意处就够了。

用户明说"不要合盘"时，严格逐张单独出，不做任何跨盘比较。

## 常见输入的处理

**"农历2000年11月20日"** → `--lunar 2000-11-20`。农历年末常已跨入次年公历，但年柱仍以立春为界，脚本已处理。

**"凌晨12点02分"** → 是 00:02。"晚上12点"多指 00:00，"中午12点"是 12:00，含糊时问清。

**"晚上8点到9点之间"** → 取中值 20:30 排盘，看真太阳时是否整个区间落在同一时辰；跨时辰则两盘并列。

**只知道大概时辰（如"下午"）** → 请用户查出生证明。实在没有：时段内只有一两个时辰的，逐个排盘并列对比；范围太宽的，用 `--time unknown` 排三柱盘。

**完全不知时辰** → `--time unknown`，按「时辰不详的三柱盘」一节写。

**出生在国外** → 用 `--lon` 给当地经度，并问清用户给的是当地钟表时间还是北京时间。
