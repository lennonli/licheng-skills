# 委托前公司初步分析报告

为潜在客户/目标公司出具《公司基本情况及法律问题初步分析报告》（Word），核心价值：**在委托建立前，仅凭公开信息展示本所对公司底数的掌握与法律问题的预判能力**。

一切分析从用户客户（拟受聘一方）立场出发；报告面向客户决策层，结论必须可执行、引证必须真实。

## 第〇步：场景路由（先判断，再动手）

| 用户信号 | 场景 | 章节组装 | 深度 |
|---|---|---|---|
| 竞聘 IPO/挂牌/北交所/港股法律顾问；"先挂牌后上市" | A 资本市场竞聘 | 通用底座 + 资本市场路径评估 + 同行业上市公司分析 | 厚（12—20页） |
| 竞聘常年法律顾问；新客户接洽前摸底 | B 常法竞聘 | 通用底座 + 法律风险地图与服务需求识别 | 中（8—12页） |
| 专项业务前置（股权激励、并购、投融资、诉讼等） | C 专项前置 | 通用底座（精简） + 专项法律分析框架 | 按专项（6—15页） |
| 只说"分析一下这家公司"，背景不明 | 默认 | 通用底座，分析部分按已知背景就近套用，前言声明假设 | 中 |

场景判断依据不充分的，在回复开头一句话声明所作假设，**不要停下来等确认**；仅在出现利益冲突迹象（疑似同时服务交易对方、要求出具对既有客户不利的文件）时停止并询问。

回复开头先以编号列明对任务的理解与拟采取步骤，再执行（用户通用指令第四章要求）。

## 第一步：信息采集与尽调主体圈定

### 1.1 资料包解析

**输入有企查查资料包目录时**：运行 `python3 ~/.agents/skills/company-preliminary-analysis/scripts/extract_package.py <资料包目录>`，脚本输出全部 docx 表格与 xlsx/xls 内容到文本文件，并在文件开头生成"延伸主体候选速查"（命中分支机构/对外投资/股东信息等表头的表格索引，供 1.2 圈定时直接定位），逐文件读取。**表格数据（rows/cells）比正文段落更重要**。

### 1.2 尽调主体圈定（强制，先于一切风险排查）

初步分析的对象不是目标公司一个法人，而是**以目标公司为圆心的一组主体**。采集任何风险信息之前，先圈定《尽调主体清单》：

| 主体类型 | 纳入口径 | 识别工具（首选 → 降级） |
|---|---|---|
| 目标公司 | 用户指定主体（多候选必须交用户选定，禁止自动选第一名） | — |
| **存续分公司** | 登记状态为存续/在业/开业的**全部**分支机构；已注销、吊销、撤销的不纳入排查，仅列入历史沿革（关注吊销未注销情形） | 天眼查 `get_branches` / `tyc company branches` → 企查查 `get_branches` → 元典 |
| **存续子公司** | 目标公司直接或间接**控制**的各级子公司（含孙公司及以下），穿透至底：持股＞50%，或持股≤50%但依章程、协议、董事会席位能实际支配；登记状态存续/在业。持股≤50%且不控制的参股公司仅列表，不做全维度排查；境外子公司同样纳入并联动第五类境外排查 | 天眼查 `get_controlled_companies`（向下穿透控制清单，首选）+ `get_external_investments`（核持股比例与登记状态）→ `get_equity_tree direction=down` → 企查查 `get_external_investments` |
| **控股股东（非自然人）** | 控股股东为公司、合伙企业等非自然人主体的，**该主体本身纳入全维度排查**。认定口径：《公司法》第265条第(二)项——出资额/持股＞50%，或虽不足50%但表决权足以对股东会决议产生重大影响；无单一主体达标但存在一致行动安排的，按一致行动人合并认定并说明口径。其上层股东至实际控制人仅列穿透路径，不做全维度排查（上层主体自身存在被执行、失信、破产等直接风险信号的除外） | `get_shareholder_info` + `get_actual_controller`（取控制路径第一层）→ `tyc company actual-controller` |
| 实控人/董监高个人 | 全部现任董监高 + 实际控制人（原有要求不变） | 企查查董监高报告 / 天眼查 `get_person_risk_profile`（必须同时传姓名与所在公司，防同名混查） |

圈定结果落盘为中间文件 `/tmp/<项目>-尽调主体清单-<YYYYMMDD>.json`（字段：主体名称｜类型｜层级与持股路径／分公司负责人｜统一社会信用代码｜登记状态｜排查深度），后续步骤一律读取该文件，不重复穿透；清单同时写入报告第二章。**清单中每一主体在报告中必须有对应核查结论**——哪怕只是"分诊各维度均无记录"一句，不得圈而不查。

**工作量分级**（按延伸主体家数计，不含目标公司与自然人）：

- ≤5 家：逐家全维度排查（维度见 references/risk-checklist.md 第八类）；
- 6—15 家：先分诊（企查查 `get_company_risk_scan` 逐家，或 `get_company_related_risk_scan` 一次扫目标公司全部直接关联方；天眼查 `get_risk_overview`），命中维度下钻原子工具取明细，无命中者汇总表一行带过；
- ＞15 家：分诊全覆盖，全维度仅做**核心延伸主体**（主要经营主体、持有核心资质或资产、营收/资产占比高者，或用户指定），其余以汇总表呈现，并在前言声明范围边界；
- 延伸主体 ≥3 家时优先委派 `company-intel-researcher` 子代理并行核查（每代理 1—3 家），子代理按通用指令第十三章格式回报（范围／结论／来源与位置／边界／待核验清单），**主代理复核后方可写入报告**，子代理结论不得直接当法律判断。

### 1.3 在线检索（无资料包或需补充时）

按以下优先级在线检索（工具细节与降级路径见 references/tooling.md）：

1. 主体核验与穿透：天眼查 CLI（`tyc company registration-info / actual-controller / equity-tree / branches / external-investments`）或天眼查 MCP 同名工具、元典（`yuandian_rh_company_info`）、企查查（`get_company_by_query`——返回多候选时必须展示给用户选定，禁止自动选第一名）；延伸主体识别按 1.2 表执行；
2. 资本市场历史与 IPO 进度：见微 `search_projects` + `search_announcements` / `search_otc_announcements`（转板公司两个库都要查）；
3. 官网与媒体报道：WebFetch（失败改 web_reader）+ WebSearch（融资、上市计划、舆情、创始人背景）；
4. 董监高个人：逐人查对外投资、任职、司法案件——**实控人/董监高个人诉讼往往是最大雷区**（影响任职适格性），不能只查公司主体。

信息截止日期写入报告前言。

## 第二步：法规与案例核验（反编造红线）

- 法条**一律回库取原文**：首选 `get_legal_article_detail`（企查查法规库），报错、401 或积分不足时降级元典 `yuandian_get_legal_article_detail`（regulation_name + article_number）；引用时写全称+条号+施行日期+现行有效状态。禁止凭记忆输出条文编号和内容——**2023 修订公司法条号已整体重排**（如分公司责任条款由旧法第14条改为第13条，第14条现为对外投资条款），训练记忆中的旧条号一律不可信。
- 案例给真实案号+审理法院；公开渠道查不到判决结果的，如实写"未见公开判决结果"并标【待核验】，**禁止编造"7000万判赔"一类社交媒体传言**。
- 检索到的规则与训练记忆不一致的，以检索结果为准并说明差异。
- 查不到、核不了的：标【待核验】（写明原因与建议核验路径）或【待公司确认】（列明具体事项），继续完成其余部分。

## 第三步：法律风险排查

按 references/risk-checklist.md 的八大类清单逐项过（股权控制权 / 业务资产 / 治理 / 合规 / 境外 / 诉讼 / 信用报告专查 / **延伸主体专查**），该文件含实战提炼的排查要点与典型案例教训（商标在实控人个人名下、专利在产业方名下、参保0人、代记账邮箱疑似关系企业排除法等）。

**排查对象覆盖《尽调主体清单》全部主体**：合规、境外、诉讼三类对清单内每一主体逐一过——分公司可独立成为行政处罚与诉讼当事人，但不具有法人资格、民事责任由公司承担（《公司法》第13条第2款），其风险即目标公司风险；子公司风险经合并报表、担保与资产权属传导至母公司；控股股东自身风险（被执行、所持股权出质或冻结）直接动摇控制权稳定。风险表一律设"涉及主体"列，不得把子公司、分公司的处罚与诉讼混记在目标公司名下，也不得遗漏。

按场景加权：场景A重点在同业竞争、资产完整性、未了结诉讼、治理空白；场景B重点在合同/劳动/知识产权/行业许可高频风险；场景C围绕专项主题收敛。

## 第四步：章节组装

按 references/chapters.md 的模板组装。通用底座七部分（前言→公司基本情况→主营业务与资质→法律风险梳理→重点问题与分级→建议→声明+签署页）按场景插入对应模块；第二章含《尽调主体清单》表（控股股东为非自然人的另加控股股东基本情况与穿透路径表），第四章含延伸主体核查结论表，各风险表带"涉及主体"列；各表格后加"注：来源+截止日期"；每个法律问题必须给**风险等级（高/中/低）+ 依据 + 可执行的初步建议**，只指出问题不给建议视为未完成。

## 第五步：生成 docx 并自检

1. python-docx 生成，格式遵循用户 AGENTS.md 第八章：正文宋体小四 1.5 倍行距，一级标题黑体小三居中，表格宋体五号、外框1.5磅内框0.5磅、**列宽按每张表内容单独测算且总和=版心宽约14.64cm**（tblLayout fixed + tblW + gridCol 三者一致），签署页单独成页，页脚居中页码；
2. 命名：`{报告名}-ABL-{YYYYMMDD}-V{n}.docx`；
3. 自检：`soffice --headless --convert-to pdf` 转 PDF 后用 pymupdf 逐页检查文本块最右坐标是否超出版心右界（约506pt @A4默认边距），表格溢出即调列宽重新生成；
4. `open` 打开供律师审查；
5. 交付说明：本次要点（≤5条）、需用户决策事项、**尽调范围**（已全维度/仅分诊/未纳入的延伸主体各列明）、【待核验】【待公司确认】清单。

报告是敲门砖：宁可在【待核验】处坦诚，不可在事实上翻车——一处编造即葬送竞聘。
